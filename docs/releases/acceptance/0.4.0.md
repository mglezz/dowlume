# Dowlume 0.4.0 acceptance

[English](#) · [Español](../../es/releases/acceptance/0.4.0.md)

> On 2026-10-24, the stable download list was reduced to the installer and two application ZIPs, now named `-portable.zip`. Only the filenames changed; the original accepted hashes below still apply. See the [current download names and checksums](../0.4.0.md#download-checksums). The rc.2 assets retain the technical reports and restricted Linux preview.

I published [0.4.0](https://github.com/mglezz/dowlume/releases/tag/v0.4.0) for macOS Apple Silicon and Windows on 2026-10-23 after manual functional confirmation of rc.1 on both platforms and automated regression/package acceptance of the rc.2 shutdown correction. Signing remains deferred. I distinguish automated evidence from final manual functional confirmation below.

## Scope

I target macOS 15+ ARM64 and ordinary local APFS folders on the same volume. I include preview, organization, monitoring, review, Keep, Snooze, Move, eligible Undo, recovery, history, settings, English/Spanish, Finder, native menus and optional login startup. I refuse cross-volume/cloud/network/link operations; Linux remains a restricted preview and recycling remains disabled. See [notes](../0.4.0.md) and [native guarantees](../../architecture/file-operations.md).

## Automated evidence

I run the full Release suite, formatting, analyzer/dependency checks, a native matrix on two newly created APFS images, and extracted-package workflow checks. Reports identify the source, dirty state, operating system and archive hashes. I do not use dirty development packages as release candidates.

Local development on macOS 26.6.2 ARM64, SDK 10.0.401, passed the supported workflow and both APFS case policies, including a full 256 MiB disposable volume. I verify native race/collision preservation, xattrs/mode/timestamps, hard-link refusal, native readiness, permissions, watcher/drain, reopened-journal recovery and cross-volume refusal before journaling. CI supplies separate macOS 15, Windows and Linux evidence. I retain the historical releases and retired Recycle Bin probes unchanged.

The macOS package script signs ad hoc, extracts the ZIP, verifies it again, and exercises its actual executable with a newly required disposable profile. The workflow report covers all tabs in both languages, persisted language, native lifecycle and Undo, reopened database and watcher shutdown. It explicitly leaves manual installation, actual login and clean-machine acceptance unclaimed.

## Exact-package checklist

I requested final checks against the hashed candidate using the following checklist. I record the overall confirmation below; I do not invent separate measurements or evidence for every item:

- macOS: extract and install the full `.app`, review any Gatekeeper/permission prompt under the actual ad-hoc signing status, and verify ordinary-user access and denied access with disposable sample files.
- macOS: upgrade a closed 0.3.0 preview profile, preserving settings, language and history; verify restart, native folder selection/Finder, Command-comma, Hide/Dock reopen, single-instance refusal, confirmation cancellation and Quit while monitoring.
- macOS: enable login startup from the installed app, sign out/in, confirm launch with monitoring paused, then disable it and verify the owned registration is removed. Uninstall retains profile and managed files.
- Windows: repeat upgrade from 0.3.0, both languages after restart, organization/review/Undo, tray and closing on the new package. Hosted automation is recorded separately from manual confirmation.

I do not reuse the old 0.3.0 confirmation. On 2026-10-23 I confirmed that rc.1 worked correctly on both macOS and Windows. I subsequently accepted the narrowly scoped rc.2 shutdown correction using the deterministic regression test, the full native matrix and final-package checks.

## Stable acceptance and publication — 2026-10-23

After receiving the rc.1 checklist, I confirmed successful testing on Mac and Windows and approved continuing publication. This is an overall functional confirmation, not a separate recorded result for every checklist item. I did not supply additional OS build numbers, clean-machine evidence, screenshots or per-step logs; I do not infer those details. The automated JSON reports retain their original `ManualDesktopAcceptance: false` fields because they describe automation, not this later confirmation.

I do not claim a second manual pass on rc.2. Its sole product change after rc.1 is watcher disposal order during shutdown. I accept that change through a regression that fails on the old code, the full suite on all three platforms, both APFS matrices, Windows upgrade/install checks and extracted-package workflow checks on macOS 15 and 26. This closes the functional release gate with the evidence stated here; separate clean-machine and per-step manual evidence remains unclaimed.

I publish [v0.4.0](https://github.com/mglezz/dowlume/releases/tag/v0.4.0) from the same `26a9087` source and preserve the installer, application archives, acceptance kit, build information and automated evidence byte-for-byte. Only standalone release notes and the affected checksum manifests are finalized after acceptance. Offline documentation inside the accepted packages describes the pre-publication state; this record and the standalone notes provide the final status. I retain the prerelease as historical evidence and make 0.4.0 the latest stable release.

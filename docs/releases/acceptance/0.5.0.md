## Candidate delivery — 2026-10-28

[0.5.0-rc.1](https://github.com/mglezz/dowlume/releases/tag/v0.5.0-rc.1) is a prerelease
for manual testing, not stable acceptance. All application binaries were built from
clean source [`e19dfe9cd8eebe0aed6268f86dbc5c92293e0e65`](https://github.com/mglezz/dowlume/commit/e19dfe9cd8eebe0aed6268f86dbc5c92293e0e65), merged through
[PR #38](https://github.com/mglezz/dowlume/pull/38). `BUILD-INFO` reports
`DirtyWorkingTree: false` for Windows, macOS and Linux. Later documentation commits
do not change the binaries. The build timestamps use UTC on October 27; candidate
delivery is dated October 28 in Europe/Madrid.

Linux ran on Ubuntu 24.04 x64, kernel `6.17.0-1022-azure`, glibc 2.39, using a newly
created disposable ext4 loop image. The runner supplies a UUID alias for its generated
volume when udev does not. The suite covers native identity/metadata, collision and
race preservation, links/FIFOs, permissions, unsupported storage, full lifecycle,
monitoring and reopened journals before/after rename. The extracted package runs under
Xvfb; this is not a real GNOME X11 or Wayland session. Fedora and Arch remain unverified.
The `.deb` was built and hashed; Linux installer execution is not covered by this smoke test.

The hosted Windows machine has shared .NET runtimes, so its successful package tests
do not establish clean-machine independence. macOS is ad-hoc signed without Developer
ID/notarization; Windows and Linux packages are unsigned. Native recycling remains disabled.

## Remaining before stable publication

### Maintainer confirmation — 2026-11-01

The maintainer confirmed that all requested manual checks of `0.5.0-rc.1` passed
and that the application works correctly. This is a maintainer-reported result for
the candidate and hashes above, not an additional automated report. Detailed guest,
desktop/backend and filesystem records were not supplied with the confirmation.

The subsequent release review fixes portable Linux menu ownership: an older copy
must not remove a newer copy's menu entry, and modified entries must be preserved.
It also updates Windows package CI to test upgrading from stable 0.4.0 with its
published SHA-256. These changes require new package evidence; the rc.1 hashes and
reports above remain historical. Final package checks and acceptance must identify
the replacement artifacts before stable promotion.

The following was the pending matrix when rc.1 was delivered:

- Run both languages through actual GNOME X11 and Wayland desktops; record the rendering
  backend, including XWayland if used. Test dialogs, reveal, scaling, close and restart.
- Test the `.deb` on a clean Ubuntu installation, upgrade/remove/reinstall and running-app
  refusal; test portable relocation, menu registration/removal and profile preservation.
- Verify opt-in startup through a real logout/login, desktop disable overrides and removal.
- Verify normal udev UUID discovery on real local ext4, cross-mount/bind-mount rejection,
  unsupported filesystem and casefold cases, advisory locks and low-space behavior.
- Force process interruption at journal/rename boundaries, reboot and power loss only on
  disposable guests. Reopened-journal fixtures do not replace these failure tests.
- Retain Windows/macOS regressions; obtain explicit final functional acceptance for the
  chosen candidate. No prior 0.4.0 manual confirmation is reused for these binaries.

Use the [Linux acceptance plan](../../development/linux-acceptance.md) to record evidence.
At rc.1 delivery, 0.4.0 remained latest stable. Final package acceptance is recorded below.

## Final 0.5.0 packages — 2026-11-01

The maintainer requested release preparation with authorization to correct issues and
confirmed that all requested rc.1 manual checks were successful. The final source is
[`09bc175b0ff2c50ceddc90ff3dbcc40f3611877e`](https://github.com/mglezz/dowlume/commit/09bc175b0ff2c50ceddc90ff3dbcc40f3611877e), integrated through [PR #40](https://github.com/mglezz/dowlume/pull/40).
Application C# and native file-operation code are unchanged from rc.1. The product
correction is confined to the portable Linux menu helper; Windows CI now upgrades
from stable 0.4.0. Three preservation regressions fail against the previous helper
and pass with the correction; POSIX CI also verifies linked-executable refusal.

| --- | --- |

| Native APFS matrix, same run | 25/25 passed on each case policy. |

| [Linux/macOS packages](https://github.com/mglezz/dowlume/actions/runs/41343648441) | Native/extracted-package workflows passed. |
| [Windows package](https://github.com/mglezz/dowlume/actions/runs/41343644971) | Upgrade from hash-pinned 0.4.0, languages, tray, running-app guards, portable launch, profile preservation and uninstall passed. |

Build metadata identifies this exact source and `DirtyWorkingTree: false` for every
platform. Package reports identify Windows NT 10.0.26100 x64, macOS 15.8.2 ARM64,
and Ubuntu 24.04 x64 with kernel 7.0.0-1017-azure / glibc 2.39. Linux tests use
disposable ext4 and macOS uses APFS. Local Windows validation also passed 93 .NET tests (46 platform skips),
formatting, documentation checks, and dependency/analyzer/secret scans. The helper's
three preservation regressions were reproduced against the old implementation on
disposable paths. No personal Downloads or retired recycle probes were used.

The maintainer's rc.1 confirmation and the final correction's automated evidence are
distinct. No second manual pass, additional clean-machine report, per-step desktop
log or native Wayland backend verification is claimed. Automation reports retain
their original false manual-acceptance fields. Linux automation uses Xvfb and a
disposable ext4 loop image; it does not independently certify real login, `.deb`
installation, physical power-loss behavior or normal udev discovery. Fedora/Arch
remain unverified. These evidence limits are retained in the published platform scope.

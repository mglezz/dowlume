[Español](../../es/releases/acceptance/0.6.0.md) · [Release notes](../0.6.0.md)

## Preparation — 2026-11-07

The maintainer requested validation and preparation of the definitive 0.6.0 release. This authorizes preparation; it is not a report of manual testing of these new binaries.

The candidate adds native periodic-organization acceptance to extracted packages, using the real one-minute minimum interval and production movers. Windows package acceptance upgrades the hash-pinned published 0.5.0 installation through the production update downloader, size/hash verifier and installer launcher. That integration supplies controlled release metadata and the actual candidate installer bytes; it does not impersonate a published future GitHub release or claim a manual button-to-installer review.

The final source revision, CI runs, package checksums and observed results will be recorded here after validation. Builds must report `DirtyWorkingTree: false`. No binary is approved by earlier 0.5.0 evidence.

## Evidence limits

Hosted runners do not establish clean-machine independence or real login, suspend/resume, physical power-loss or human desktop acceptance. Linux uses Xvfb and disposable ext4, not a real GNOME Wayland session. macOS requires native APFS checks. Windows/Linux remain unsigned; macOS remains ad-hoc signed. Native recycling stays disabled. Any unperformed checks must remain explicit when deciding publication status.

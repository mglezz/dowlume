# Dowlume 0.7.0 — Personalization and controlled automation

[Español](../es/releases/0.7.0.md) · [User guide](../user/guide.md) · [Release procedure](../development/releasing.md)

**In preparation.** This source version is not a published stable release. The public downloads remain 0.6.0. Candidate CI packages do not constitute final-package or clean-machine acceptance.

## Included since 0.6.0

- Light, dark, and system appearance, saved per profile and applied immediately.
- An On/Off monitoring switch and opt-in automatic resumption when Dowlume opens. First use still requires preview and confirmation; changed organization rules revoke that consent. Turning monitoring off also disables automatic resumption.
- Optional whole-folder collection, disabled by default, with a separate 20–1440 minute schedule and configurable collection folder. Two stable observations are required; collisions, incomplete downloads, links, hidden/system folders and classification folders are left alone. Moves are recorded in Activity without automatic Undo or file aging.
- Windows login startup in the tray by default, with a saved option to show the window. Existing startup registrations are upgraded without enabling disabled registrations. This was merged after the 0.6.0 release.
- Editable classification folders and up to 50 custom rules by extension, filename contains, or filename starts with. Duplicate assignments are rejected; ambiguous name matches remain untouched. These changes were also merged after 0.6.0.
- Hidden windows no longer query the overview and activity every three seconds. Folder inspection is bounded to 10,000 entries per tree and uses metadata observations without hashing all file contents.

## Behavior and limits

Older profiles default to System appearance, monitoring off, and folder collection off. Existing languages, rules, files and history are retained. Enable automatic resumption only after inspecting the current preview. File and folder timers wait again after restarting; Dowlume must remain running.

Folders move as complete directories by exclusive same-volume native rename. No merging, deletion, cross-volume copy or recursive reclassification is performed. POSIX sharing locks are cooperative; a stable observation cannot guarantee that another application will never reopen content. Folder operations interrupted around a filesystem/database commit require manual inspection and are never replayed automatically. Keep working folders outside the monitored Downloads root.

The [guide](../user/guide.md) describes settings, preview, recovery and supported filesystem limits. Final release publication remains subject to the normal package validation and acceptance procedure.
